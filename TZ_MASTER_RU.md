### Правила повышения качества
- Слабые сигналы должны переходить в `NO TRADE`, а не маскироваться высоким confidence.
- Направление подтверждается несколькими независимыми факторами.

### D. High-Conviction Engine
- Сигнал формируется только после независимого голосования факторов.
- Система различает `LONG`, `SHORT`, `NO TRADE` и уровни силы сигнала.
- `HIGH CONVICTION` допускается только при одновременном выполнении строгих условий по направлению, историческому edge, MTF agreement, качеству данных, ликвидности/объёму и R/R.
- При конфликте факторов confidence автоматически снижается.
- При недостатке подтверждений модель обязана выбрать `NO TRADE`.
- **100% точность не обещается:** рынок не позволяет гарантировать результат. Цель модели — повышать вероятность и качество отбора, а не выдавать ложную уверенность.

### E. Калибровка вероятности
- Confidence не равен простому нормированию score.
- Confidence должен учитывать walk-forward directional edge, gap LONG/SHORT, MTF agreement, regime, data quality, volatility и качество R/R.
- При малой выборке исторических наблюдений confidence ограничивается.
- Backtest/walk-forward не использует будущие данные для текущего прогноза.
- Результаты тестов разделяются на in-sample и out-of-sample, когда объём истории это позволяет.

Рядом с каждым действующим прогнозом обязательна кнопка **«Отслеживать» / «Track»**.
- Нажатие создаёт один уникальный tracking-id.
- Отдельно контролируются Entry, TP1, TP2, TP3 и SL.
- После каждого события пользователь получает уведомление.
- Дубли одного события запрещены.
- В карточке отслеживания отображается live-цена БКС, изменение от Entry и прогресс до следующего уровня.

### H. Сканер
- Обычный сканер сохраняет прежнюю логику настроек периодичности и не получает лишних настроек единиц времени.
- Сканер использует только БКС.
- При обнаружении валидного сигнала результат появляется **сразу в списке сканера**, а затем отправляется уведомление.
- Нельзя ждать завершения полного сканирования, чтобы показать уже найденный сигнал.
- Параллельная обработка ограничивается, чтобы устройство не зависало.
- Уже найденные сигналы дедуплицируются по `instrument + timeframe + signal + event`.

### I. Уведомления WOW
Категории:
- 🟢 LONG;
- 🔴 SHORT;
- 🟡 NO TRADE / предупреждение;
- 🎯 TP1/TP2/TP3;
- 🛑 SL;
- 📡 новый сигнал сканера;
- 📰 важная новость;
- 💰 дивиденды;
- 📊 завершение прогноза.

Каждое уведомление содержит инструмент, направление, confidence, live-цену БКС и ключевой уровень события. Нажатие открывает соответствующий прогноз/отслеживание.

### J. Языковой контракт — ОБЯЗАТЕЛЬНО
- Если выбран русский язык — **весь пользовательский текст только на русском**, включая ошибки, статусы, уведомления, кнопки, пустые состояния, подсказки, заголовки, историю, сканер и настройки.
- Если выбран английский — **весь пользовательский текст только на английском**.
- Названия API/тикеров/математических обозначений (`EMA`, `RSI`, `TP1`, `SL`, `BCS`) не переводятся, если это технические обозначения.
- Запрещены случайные русские строки в английском режиме и английские строки в русском режиме.
- Все новые строки добавляются через `ru ? ... : ...` или централизованный словарь локализации.
- Не допускается фиксированный `Color.White`/`Color.Black` для обычного текста: текст использует `MaterialTheme.colorScheme.onSurface` / `onSurfaceVariant`.

### K. График PRO
- Одна математическая `priceToY()` функция используется для свечей, live-marker, Entry, SL, TP1/TP2/TP3, S/R, сетки и шкалы.
- При масштабировании графика уровни остаются прикреплены к своим ценам.
- Подсказка по точке показывает OHLCV и время свечи.
- Live-цена визуально отделена от исторической свечи, но использует ту же шкалу.

### L. Контроль качества данных
Для каждого набора данных вычислять:
- freshness/возраст live-котировки;
- полноту OHLC;
- количество пропусков;
- корректность high/low/open/close;
- временную последовательность свечей;
- наличие достаточной истории;
- соответствие инструмента БКС.

При неудовлетворительном качестве прогноз блокируется или переводится в `NO TRADE`.

### M. Производительность и задержка
- Live quote имеет отдельный короткий кэш.
- Исторические свечи кэшируются отдельно.
- Аналитика выполняется вне UI-потока.
- Сканер обрабатывает инструменты параллельно, но с ограничением конкуренции.
- Приоритет: текущий прогноз → сканер → избранное → вторичные данные.
- UI не должен блокироваться сетевыми запросами.

### N. Статистика и самообучающийся контроль качества
- Сохранять фактические исходы прогнозов.
- Строить статистику отдельно по инструменту, таймфрейму, направлению и режиму рынка.
- Показывать win-rate, average R, profit factor, max drawdown и количество сделок только при достаточной выборке.
- Использовать накопленную out-of-sample статистику для калибровки confidence, не подглядывая в будущие данные.
- При деградации качества автоматически усиливать фильтр `NO TRADE`.

### O. Финальный критерий «готово»
Версия считается законченной только если одновременно выполнено:
- БКС подключён и является единственным рыночным источником;
- одна и та же цена отображается на всех экранах/таймфреймах;
- прогноз и график используют один набор данных;
- нет скрытых fallback-источников;
- поиск акций и валют работает через БКС-каталог;
- сканер показывает найденный сигнал без ожидания полного цикла;
- отслеживание работает end-to-end;
- уведомления работают по событиям;
- русский/английский режимы не смешивают языки;
- график математически привязывает все уровни к цене;
- аналитика проходит walk-forward/backtest-проверку;
- `:app:assembleDebug` проходит без ошибок;
- APK устанавливается поверх предыдущей версии без смены applicationId и без сброса данных.
